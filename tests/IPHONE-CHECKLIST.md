# iPhone Safari / ホーム画面PWA：公開前の実機確認（未実施）

## Ver.0.2で追加して確認する項目（今回の実機確認は未実施）

Ver.0.1.1の実機成功と、Ver.0.2の実機確認は別です。以下をSafari通常モード・ホーム画面PWAの両方で行い、機種・iOS・結果を記録してください。本番とは別のHTTPSホスト・テスト専用DBを使います。以前のNetlifyパッケージはVer.0.1.1なので流用しません。

実際のGPS座標を取得せず、試験用コピーのGeolocation APIと気象APIを固定の架空応答に置換した環境で確認します。ブラウザの実際の許可画面は「許可しない」の経路を確認し、許可後の成功・タイムアウト・遅延応答は模擬APIで検証します。実GPS・外部APIを使う試験は今回の範囲外です。

| 項目 | 合格条件 |
|---|---|
| 初回起動 | 両設定がオフ。位置の許可要求・API通信が勝手に始まらない |
| 天気のみ有効 | 9項目・取得元・取得日時・対象日時を表示／保存。バックアップに正確な位置が入らない |
| 位置のみ有効 | 模擬測位が1回。天気APIの通信はなく「記録した場所」に保存。「出来事の場所」は空 |
| 両方有効 | 同じ記録で測位を共有し、画面の出入りや天気再取得でGPSを繰り返し起動しない |
| 許可拒否・測位失敗 | 状態を表示し、本文・写真・感情を引き続き保存できる |
| API失敗・オフライン | 手入力と保存が可能。取得済みの位置を天気失敗で失わない |
| 過去日時 | 自動入力の天気を除去し、現在地を出来事の場所に自動設定しない |
| 手修正中の応答 | 入力済みの気象値や編集中の場所を上書きしない |
| 保存直後の遅い応答 | 別の日記や次の入力フォームへ混入しない |
| 同意撤回 | 入力中の座標を除去し、未完了の応答で復活しない。別タブの設定変更も反映 |
| 場所の編集／削除 | 記録場所と出来事の場所を別々に変更でき、本文・写真・追記は保持 |
| 旧データ・バックアップ | Ver.0.1.1の既存記録は位置なしで表示。形式1・2の復元、追加気象値・位置の完全一致を確認 |
| PWA更新 | updates.js・environment.jsを含めて検証し、入力を保存してから画面を更新。オフラインでも本文保存可能 |
| 小さい画面・キーボード | 上部要約が本文入力を妨げず、設定チェック・詳細の場所編集が操作できる |

以下の旧版向け一覧も、Ver.0.1.1 → Ver.0.2の更新に読み替えて実施してください。

この一覧は実施結果ではありません。各項目をSafari通常モードとホーム画面PWAの両方で確認し、iPhone機種・iOSバージョン・実施日・結果を記録してください。

## 準備と分離

- 本番とは異なるホスト名のHTTPS検証サイトを使う。同じホストの別パスだけではIndexedDBは分離されない。
- 検証版のDB名を `kioku-test-iphone` に差し替え、本番DB名へのアクセスを禁止する。配布用コードは書き換えず検証コピーで実施する。
- 架空の文章、JPEG/PNG/WebP画像、複数の感情、複数の追記、入れ子の未知フィールドを持つ記録を使う。個人の日記や写真を持ち込まない。
- 旧版の試験用バックアップを「このiPhone内」などに保存する。SafariとPWAの保存領域が同じだと仮定しない。それぞれで試験データを作成する。

## 実機テスト表

| 項目 | 操作 | 合格条件 |
|---|---|---|
| 旧版から更新 | 検証サイトのv0.1で複数記録を保存し、v0.1.1へ更新する | 件数・ID・本文・写真・感情・追記・未知項目がバックアップ比較で一致する |
| 更新待ち | 旧版を複数タブとPWAで開いたまま新版を配布する | 入力中の画面が強制再読み込みされず、既存記録も維持される |
| 新版への切り替え | 入力を保存後、旧版では再読み込み、新版では「更新する」を押す | 新版が起動し、必要ファイルが揃い、旧記録が表示される |
| 一部配布の失敗 | 検証サーバーでJSを404または異なる内容にする | 新SWの導入が失敗し旧SWを保持する。新版HTMLが先に届いた場合はエラーを表示し操作を無効にする |
| オフライン起動 | 新版を正常起動後、機内モードで閉じて開く | 保存済み記録と写真が表示でき、架空の新規記録・追記を保存できる |
| 起動失敗 | JSを読み込めない検証状態で起動する | 保存・復元・削除が無効になり、データを削除しないよう案内する |
| 復旧 | 検証サーバーを正常化し再起動する | 日記を初期化せずに起動できる。キャッシュ欠損の復旧も別途確認する |
| 形式1の復元 | v0.1が作成した架空JSONをFilesから選ぶ | 未登録分のみ追加し、写真・感情・追記を含め一致する |
| 形式2の復元 | v0.1.1から書き出し、別の空の検証DBへ取り込む | 全フィールドが一致する。元DBを消して試験しない |
| 競合・キャンセル | 同じIDで本文や追記が異なるJSONを選ぶ／確認をキャンセル | 相違を表示し、既存内容を保持する。キャンセル時は追加もない |
| 不正バックアップ | 検査値不一致、件数不一致、未来の形式、壊れた画像を取り込む | 復元を停止し、既存DBの内容が変わらない |
| ダウンロード中断 | 保存先選択・共有画面を閉じる／キャンセルする | 「保存完了は未確認」のままで「保存成功」と表示しない |
| 保存完了確認 | 「このiPhone内」とiCloud Driveにそれぞれ保存する | Filesでファイルの存在・サイズを確認し、実際に復元できる。共有画面の終了だけを成功扱いしない |
| 同時追記 | 複数タブで同じ記録に異なる追記を保存する | 両方の追記が残る（保存領域が同じタブ間で確認） |
| 大容量・容量不足 | 検証端末で大きな架空バックアップや空き容量不足を試す | フリーズや終了の有無を記録し、失敗後の既存データが一致する |
| 再起動・中断 | 復元中にバックグラウンド移動・アプリ終了・端末再起動を試す | 一部だけの追加や既存記録の破損がない。復元前後のJSONで検証する |
| 削除のキャンセル | 既存の単件削除・全削除の確認をキャンセルする | 既存データを保持する |

WebKitのストレージ保持、iOSの共有・ダウンロード、実際の容量不足、OSによる強制終了は、Chromeの自動テストだけでは保証できません。ブラウザデータの消去やアプリ削除を復旧手順として案内しないでください。
