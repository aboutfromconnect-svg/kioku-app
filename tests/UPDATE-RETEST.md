# Ver.0.2 更新修正・再テスト

## 原因と修正

旧WorkerはHTMLをキャッシュ優先で返し、新Workerは旧画面が閉じるまで待機していました。旧画面には更新通知と明示的な更新確認がありません。この組み合わせで、通常Safariだけが旧画面を表示し続ける経路を確認しました。ユーザーのiPhone上のWorker状態を直接調査した結果ではありません。

修正後は全ファイル取得、HTMLの版番号確認、3個のJSのSRI（ファイルの内容が正しいかを確かめる検査値）検証とキャッシュ保存が終わってからWorkerを有効化します。強制再読み込みはしません。旧キャッシュも保持するため、開いた旧画面の入力と旧JSを維持できます。IndexedDBへの処理はありません。

updates.jsは起動時、画面復帰時、設定の「更新を確認」で確認します。新版を検出すると「新しいバージョンがあります」と通知します。「更新する」は未保存の日記・追記・場所の編集や保存処理中には再読み込みせず、保存を案内します。入力の有無は非同期確認の前後で調べます。通信確認は15秒で打ち切り、再試行できます。

Workerの有効化と画面の更新は別です。旧Ver.0.1.1の画面に通知機能を後付けすることはできません。ただし旧コードを再配布しなくても、ブラウザーが修正版Workerを取得すれば、保存後の手動再読み込みで移行できます。Safari自体が更新確認を実行する時刻やOSによる中断は制御できません。

## Windowsから再配布

1. `netlify-test-package/v0.2` フォルダーを使用します。修正版識別子は `0.2-netlify-test2`、DBは `kioku-test-iphone` です。フォルダー直下にindex.html、service-worker.js、updates.js、environment.js、data-safety.js、manifest.webmanifest、icons、_headers、robots.txtがあります。
2. Netlifyで、これまで使っているテストサイトを開き、そのサイトのDeploysにある手動アップロード領域へこの **v0.2フォルダー全体** をドロップします。新しいサイトを作成しないでください。親フォルダーやリポジトリ全体をアップロードしません。
3. 配布完了後も同じ通常のサイトURLを使います。個別デプロイのプレビューURLに切り替えません。プライベートモードは既存データの引継ぎ確認には使いません。

## iPhoneでの再確認（実機では未実施）

Safari通常モードと既存ホーム画面PWAのそれぞれで実施します。両者の保存領域が同じとは仮定しません。日記・写真は架空のものを使用してください。

1. 旧画面の入力・追記を保存し、テスト用JSONバックアップをFilesに保存します。件数、本文、写真、感情、追記を控えます。
2. 配布後、オンラインで同じURLを開いて再読み込みします。初回は旧キャッシュの画面が先に表示される場合があります。しばらく待ってから、入力が保存済みであることを確認して再読み込みしてください。PWAに再読み込み操作がない場合は、保存後に終了して同じアイコンから開き直します。再インストールは不要です。
3. 設定に「更新を確認」が現れること、天気・位置設定が表示されることを確認します。旧日記の件数・本文・写真・感情・追記を照合し、JSONの保存・復元を試します。実GPSは同意した場合だけ取得されます。座標入りバックアップはリポジトリに入れないでください。
4. 複数タブとPWAを開いた状態でも、配布だけで入力が消えないことを確認します。今後の別版配布時は、未保存入力がある状態で「更新する」を押すと止まり、保存後には切り替わることを確認してください。同じ版の再アップロードでは新版通知は出ません。
5. 機内モードで「更新を確認」を押しても日記が失われず、本文を保存できることを確認します。オンラインに戻して再試行します。
6. 改善しない場合は、URL、iOSの版、Safari/PWAの区別、表示内容を記録してください。サイトデータ消去、キャッシュ全消去、PWA削除は行いません。

## 制約

自動テストは隔離Chromium・ローカルサーバー・架空データで実施します。Safari/WebKitの実機動作、バックグラウンド復帰、OSのストレージ整理は実機再確認が必要です。旧キャッシュは開いた旧画面を保護するため保持し、容量不足で更新できなければ旧版を維持します。将来、使用中の旧版を確実に判定できる削除方針が必要です。ブラウザー自身の更新・終了操作やOSの強制終了まで未保存入力を永続保存する機能ではありません。

ライフサイクル参考: https://web.dev/articles/service-worker-lifecycle
