# kioku v0.1.1 — 自分専用の記憶ログ

公開前の最終確認とGitHub Desktopでの手順は [RELEASE.md](RELEASE.md) を参照してください。Netlify用コピーは本番配布に使用しません。

感情が動いたときにすぐ一行、必要なときだけ状況・理由・天気・体調などを足せる、iPhone向けの個人用Webアプリです。

## できること
- 日時付きの出来事・日々の状態の記録、複数の感情タグ
- 写真を3枚まで添付（長辺1280px程度に縮小して保存）
- 任意の状況・理由・睡眠・体調・疲労・天気・気温・気圧・湿度・風速
- 現在地の天気をボタンを押した時のみOpen-Meteoから取得
- 記録の検索、日付絞り込み、振り返り、追記（元の文章を上書きしない）
- JSONバックアップ・復元（同一IDは重複登録しない）
- 本文や写真はIndexedDBにローカル保存、ログイン・アカウント不要
- 静的ファイルのオフラインキャッシュ（HTTPS上での導入後）

## iPhoneでホーム画面アプリとして使う

このフォルダ内のファイルを **まとめてHTTPSの静的Webホスティング** に公開してください。`index.html` だけでなく `data-safety.js`、`manifest.webmanifest`、`service-worker.js`、`icons/` も必要です。

### GitHub Pagesを使う場合
1. GitHubに新しいリポジトリを作成（個人の感情を記録するアプリの **コードのみ** を置く。日記データはアップロードしない）。
2. このフォルダ内のファイルを、階層を保ってリポジトリのルートにアップロード。
3. リポジトリの Settings → Pages → Build and deployment → Deploy from a branch → main / (root) → Save。
4. Pagesの公開URLをiPhoneのSafariで開く。
5. Safariの共有メニュー → 「ホーム画面に追加」。以後は追加したアイコンから起動する。

※ GitHub Pagesのサイトは通常インターネット上で公開されます。公開されるのはアプリのコードで、個人の日記は各端末内に保存されます。機密の本文をHTMLやGitHubに書き込まないでください。
※ 公開URLを削除したり、ブラウザ／ホーム画面アプリのデータを消したりすると、記録が失われる場合があります。バックアップを別の保存場所に定期保存してください。

### Windowsで動作確認する場合
このフォルダで `python -m http.server 8000` を実行して、PCブラウザで `http://localhost:8000` を開きます。localhostは開発用途のため保存できます。iPhoneからPCのIPアドレスへHTTP接続しても位置情報やPWAは動かない場合があります。

## バックアップの注意
- 設定 → 「すべての記録を書き出す（JSON）」を定期的に使ってください。写真も含まれるのでファイルは大きくなる場合があります。
- iPhoneのSafari版とホーム画面アプリ版でデータが別扱いになることがあります。普段記録する側をひとつ決めてください。
- 設定 → 復元からJSONを読み込めます。重複IDの既存の記録は変更せず、ない記録のみ追加します。
- iCloud同期や端末間の同期はありません。

## プライバシー
日記本文・写真は端末内のIndexedDBに保存します。天気取得の際だけ、利用者がボタンを押すと、ブラウザの位置情報許可を経て取得した緯度・経度をOpen-Meteo（外部サービス）に送ります。位置座標は日記に保存しません。アプリには自動分析・外部同期機能はありません。

## 制約
- HTTPSでの公開・ホーム画面登録は利用者自身が行う必要があります。HTMLファイルをiPhoneの「ファイル」アプリで直接開く方式は、ブラウザの保存機能が動作しないことがあります。
- Safariのプライベートブラウジングは、保存の永続性が保証されません。
- 記録を直す場合は、原文を書き換える代わりに「追記」を残す設計です。
- 天気取得は「現在の天気」です。過去日の出来事には自動対応していません。

## v0.1.1のデータ保護

- DB名は `kioku-personal-v1`、DBバージョンは `1` のままです。既存記録の一括変換・削除は行いません。
- 新規バックアップは形式バージョン `2`。アプリのバージョン、バックアップ形式、各記録の `schemaVersion` は別の番号です。
- 形式1（旧版が書き出した全フィールドを持つJSON）も読み込めます。未知の記録フィールド・追記フィールドは削除せず保持します。未対応のバックアップ形式や記録の構造バージョンは読み込みを停止します。
- 形式2には `entryCount` と `integrity: { algorithm: "SHA-256", entriesHash: "..." }` を保存します。検査値は、記録配列全体のオブジェクトのキーを再帰的に並べ替えたJSONのUTF-8表現から算出します。配列の順序は保持します。本文・ID・感情・写真・追記・未知のフィールドをすべて検査対象にします。
- 検査値は偶発的な破損の検出用で、暗号化や送信者の証明ではありません。形式1には検査値がないため、作成後の改変を完全には検出できません。
- 型・日時・IDの重複・画像形式を検証し、画像が実際に読み込めることも確認します。不正な値を黙って削除・短縮・置換せず、復元全体を停止します。旧版の取り込み機能で生成された不正な追記日時なども停止対象です。元ファイルと既存DBはそのまま保持してください。
- 同一ID・同一内容はスキップ。同一ID・異なる内容はIDと件数を確認画面に表示し、既存記録を保持します。内容の自動統合はしません。
- 確認後に対象記録が変更された場合は復元を中断します。追加・全件読み戻し・照合を同じDBトランザクション内で行い、エラー時は追加分をすべて取り消します。
- 追記は同じトランザクションで最新の記録を読んで追加するため、別タブの追記を古い画面の情報で上書きしません。削除された記録を追記操作で復活させません。
- バックアップ作成・ダウンロード開始と、利用者の保存先への保存完了を区別します。画面には「保存完了は未確認」と表示します。保存先でファイルを確認してください。
- 書き出し・読み込みとも120MiBが上限です。上限超過や検証失敗時に不完全なバックアップを作成しません。分割バックアップは未対応です。
- **形式2のバックアップを旧版v0.1で復元しないでください。** 旧版は形式番号を確認せず未知のフィールドを捨てます。v0.1.1以降の対応版で復元してください。

## 分離環境でのテスト

`tests/run.cjs` はNode.jsとPlaywrightを使います。Playwrightを解決できる環境で以下を実行します。

```text
node tests/run.cjs
node tests/update-safety.cjs
```

必要に応じて `NODE_PATH` にPlaywrightが入ったnode_modulesの場所、`CHROME_PATH` にChrome実行ファイルを指定します。未指定時はPlaywrightのChromiumを使います。

- 一時ブラウザプロファイルとランダムポートの127.0.0.1サーバーだけを使用します。
- 本番DB名でのopen/deleteを例外で遮断し、DB名を `kioku-test-*` に限定します。UIテスト用HTMLのDB名はサーバーがメモリ上で差し替えます。本番ファイルは書き換えません。
- `run.cjs` は外部通信とService Workerを遮断します。`update-safety.cjs` は実際のService Workerを使用し、ブラウザのホスト名解決を127.0.0.1に限定します。実際の個人日記・ブラウザプロファイルを使いません。
- JPEG・PNG・WebPの架空画像、架空の日記・感情・追記で検証します。
- 旧形式、新形式、未知フィールド、破損、競合、同時追記、書き込み失敗、照合失敗、UI上の保存・復元・キャンセルを確認します。

実端末のSafari／ホーム画面PWA、実ストレージの容量不足、Service Worker更新の実機確認は別途必要です。テスト用の書き込み失敗は意図的に発生させたものです。更新を公開するときは関連ファイルをまとめて配布し、既存バックアップを別途保管してください。

## v0.1.1の更新時の安全性

- `index.html` と `data-safety.js` にリリース識別子を持たせ、スクリプトのURLにも同じ識別子を付けています。
- HTMLのSRI（読み込むファイルの内容を検査値で固定する仕組み）とService Workerの取得時検査により、異なるJSの実行を防ぎます。読み込めない場合や識別子が合わない場合は、DBを開く前にエラーを表示し、保存・復元・削除を無効にします。
- Service Workerは全ファイルの読み込み・整合性確認を終えてからキャッシュします。応答本文は都度読み切り、各取得の待ち時間は15秒で打ち切ります。導入失敗時は旧Workerが残ります。
- `skipWaiting()`を使わず、旧Workerが制御する画面を閉じてから新版を有効にします。HTMLだけをネットワークから独立更新しません。
- 旧v0.1のWorkerはネットワーク優先のため、移行中に新版HTMLを先に配信する場合があります。その場合も、HTMLで指定した検査値に一致するJSだけを実行します。未配布なら安全に停止します。
- アプリキャッシュの整理とIndexedDBは独立しています。更新による日記DBの削除・初期化・一括上書きはありません。従来の利用者確認付き単件削除／全削除機能は残っています。
- キャッシュの欠損時は安全停止を優先します。キャッシュ自体が破損した場合の自動修復は未実装です。日記を含むサイトデータ全体の消去を復旧手段にしないでください。

開発時に`data-safety.js`を変更したら、HTMLの`integrity`とWorkerの`INTEGRITY`を同じSHA-256値へ更新してください。`.gitattributes`でJSの改行をLFに固定しています。新しい配布内容には新しいリリース識別子とキャッシュ名を割り当て、HTML・JS・Workerをまとめて配布します。`tests/update-safety.cjs`は検査値の不一致を検出します。

参考：[Service Workerの更新](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers)、[SRI](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Subresource_Integrity)。実機確認表は[tests/IPHONE-CHECKLIST.md](tests/IPHONE-CHECKLIST.md)、今回の結果は[tests/SAFETY-REPORT.md](tests/SAFETY-REPORT.md)を参照してください。
